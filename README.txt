STA ver.0.2.1 — オフライン起動・安全更新

【変更点】
元版0.2.0のsw.jsは ./、index.html、manifest.json、icon192.pngだけを保存していました。
phrases.js、画像2枚、icon512.pngが対象外でした。
今回は必要な8ファイルを保存します。外部CDNの参照はありません。
index.html：HOME右上に小さな更新ボタン、ver.0.2.1を表示。更新専用JSの読込を追加。
pwa-update.js：更新確認、保存完了の待機、切替・再読込、失敗表示。
sw.js：ファイルのSHA-256照合、版別キャッシュ、保存済みファイルを優先して起動。
phrases.js、manifest.json、画像・アイコンは元ファイルと完全一致。
フレーズ選択・音声・手書きなどの既存操作コードも変更していません。

【公開方法】
ZIPを展開し、従来STAを公開している同じ場所に9ファイルを上書きしてください。
index.html / phrases.js / manifest.json / sw.js / pwa-update.js
icon192.png / icon512.png / route-map.png / language-guide.png
全ファイルを一緒に公開し、sw.jsは最後にアップロードしてください。
README.txtとmaintenanceフォルダーは公開しなくても動作します。
PWAにはHTTPS（開発時はlocalhost）が必要です。ファイルのダブルクリックでは保存されません。

【0.2.0から初めて移行するとき】
旧版には更新ボタンがないため、公開後にオンラインでSTAを開き、少し待ってから
STAと同じURLを開いているChromeのタブ・アプリをすべて閉じて再度開いてください。
旧版が残る場合はオンラインでもう一度開き直してください。
HOME右上がver.0.2.1になれば移行完了です。以後は「更新して再起動」を使えます。
閲覧データの削除は通常の更新手順にしないでください。

【PCでの確認】
・HOME右上にver.0.2.1と更新ボタンがある。
・4言語でフレーズ一覧→選択→表示。カテゴリ移動、HOMEへの復帰。

オフライン応答、フレーズ・画像取得失敗、内容不一致時のインストール失敗と旧版保持、
明示的な切替指示、元データ・既存操作コードの一致を確認しました。

実際の新版公開後の切替も上記実機手順で確認してください。

【更新の仕組み】
通常は保存済みの同一版から表示します。裏で新版の取得が始まる場合もありますが、
利用中は勝手に切り替えず、更新操作または全タブ終了後の起動で新版へ移ります。
更新操作はオンラインのsw.jsを明示的に確認します。
新しい全ファイルの内容照合と保存が成功してから切替可能になります。
旧キャッシュは安全優先で保持しています。更新回数に応じて保存容量は増えます。
他のPWAのキャッシュや登録を消す処理はありません。

【次回の改修担当者へ】
内容を変更した際はバージョンを上げ、maintenance/release.cjsを実行して
sw.jsのSHA-256一覧を必ず再生成してください。再生成しないと更新は拒否されます。
例：node maintenance/release.cjs 0.2.2
Node.jsが必要です。生成後の全ファイルを同時に公開してください。
